# Builder Brief — 2026-06-24

## TL;DR
The strongest signal today is **agent memory fragmentation**: every coding agent ships its own context format (CLAUDE.md, AGENTS.md, cursor rules), and developers are hand-syncing the same context across all of them. Two of the top three signals are variations of "agents can't remember"—format duplication and lost reasoning between sessions. There's a real gap for a portable, tool-agnostic memory layer before one vendor's format wins by default.

## Opportunities

### Universal agent memory/instruction format
**Problem:** Developers duplicate the same context across CLAUDE.md, AGENTS.md, cursor rules, and more just to keep memory consistent as they switch tools.
**Why now:** Agent CLIs are proliferating faster than any standard. Every new entrant adds a format; the duplication tax compounds weekly.
**Who'd pay:** Multi-tool teams and individual power users juggling 2+ agents. Likely a freemium dev tool, or an open standard with paid sync/hosting.
**Buildability:** High. A single source-of-truth file + adapters that generate each tool's native format is a weekend MVP. Hard part is adoption, not engineering—get the adapters right and seed the standard.

### Persistent reasoning/intent capture across agent sessions
**Problem:** Agents generate code but drop the "why." Teams lose decision context every session, leaving undocumented choices in the codebase.
**Why now:** As agent-written code share grows, the missing rationale becomes a real maintenance and review liability.
**Who'd pay:** Engineering teams with compliance/review needs; orgs scaling agent usage past prototypes.
**Buildability:** Medium. Capturing intent is easy; making it *trustworthy and retrievable* (not just a transcript dump) is the hard, defensible part. Overlaps heavily with the memory-format opportunity above—consider building both as one product.

### AI PR/issue spam filter for maintainers
**Problem:** Open-source maintainers are drowning in AI-generated PRs, issues, and bogus vuln reports with no tooling to triage.
**Why now:** Maintainers are openly blanket-banning AI PRs—"PR spam looks like email spam circa 2000." The frustration is loud and organized.
**Who'd pay:** Tricky. Maintainers are notoriously low-budget; monetization likely runs through GitHub-app freemium or org/enterprise tiers, not individual maintainers.
**Buildability:** High. A GitHub App scoring PR/issue authenticity (heuristics + LLM signals) is shippable fast. Market score is the soft spot—validate willingness to pay before going deep.

### Lightweight per-commit AI code/security review
**Problem:** Devs want cheap, automatic security/code review on every commit—especially in plugin ecosystems leaking zero-days.
**Why now:** "AI found 300 WordPress plugin zero-days in 72 hours." The asymmetry between automated attackers and manual review is widening fast.
**Who'd pay:** Plugin authors, agencies, and security-conscious teams. Usage-based pricing fits naturally (per commit/repo).
**Buildability:** High, but crowded—existing builder (git-lrc) plus incumbents. Differentiate on price + ecosystem focus (e.g., WordPress/plugin-specific rules) rather than generic review.

### `--dry-run` for destructive CLI commands
**Problem:** Commands like `docker prune` have no preview; you can't predict what gets deleted until it's gone.
**Why now:** Evergreen pain, freshly surfaced. Low frequency but high blast radius.
**Who'd pay:** Probably nobody directly—this is a PR to upstream or a thin wrapper CLI, not a business. Good portfolio/credibility play or open-source contribution.
**Buildability:** High. Small surface area, clear spec.
`pain 4 / freq 3 / build 4 / market 3 / interest 4`

### Playwright pause-on-failure flag
**Problem:** No `--debug-on-fail` in Playwright; debugging outside the IDE means manually adding `await page.pause()` and rerunning.
**Why now:** TestCafe already has it—clear feature gap, clear precedent.
**Who'd pay:** No direct revenue; this is an upstream contribution or a plugin. Worth it for visibility in a heavily-used tool.
**Buildability:** High, narrow scope.
`pain 4 / freq 3 / build 4 / market 3 / interest 4`

### Sandbox/filesystem restriction for agent CLIs
**Problem:** Agents like opencode lack built-in containment—no equivalent to macOS seatbelt used by gemini-cli/codex-cli for restricting file/terminal access to the working dir.
**Why now:** As agents run more autonomous terminal commands, blast-radius containment becomes table stakes. Low frequency signal today but trending toward mandatory.
**Who'd pay:** Security-conscious teams running agents in real codebases; could be an open-source layer or a feature inside an agent platform.
**Buildability:** High on macOS/Linux (existing sandbox primitives); cross-platform is harder. Watch this—frequency is low now but will spike.
