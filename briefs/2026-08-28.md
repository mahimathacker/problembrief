## TL;DR
Today's ideas are all about AI models and agents. None are strong enough to build right away because big companies could easily make them. But there are some interesting problems around running big AI models on small computers and making AI agents safe.

## Research Leads
These ideas need more checking before you build anything.

### Efficient MoE Model Inference on Consumer GPUs
**Category:** AI agents
**Problem:** Big AI models need too much memory to run on normal computer graphics cards.
**What's already out there:** No clear competitor yet.
**Who'd pay:** Developers and small teams who want to use big AI models on their own computers.
**How you'd win:** Help big AI models run well on graphics cards with little memory, where they usually fail.
**First build:** A tool that lets one specific big AI model run on a common graphics card (like one with 8GB memory) at a good speed.
**Niche test:** Very specific: developers trying to run Mixtral 8x7B on an 8GB VRAM GPU. Niche score: 3/5.
**Boring test:** This is a technical problem about making software run better, which is often boring but needed. Boring score: 4/5.
**Big-company risk:** high. Big AI companies like Hugging Face or PyTorch could add this feature.
**Confidence:** medium. Big AI frameworks might just add this feature themselves.
**Sources:** [GitHub](https://github.com/ggml-org/llama.cpp/issues/26448), [GitHub](https://github.com/deepbeepmeep/Wan2GP/issues/2056)

### MoE Serving on Apple Silicon
**Category:** Devtools
**Problem:** Developers can't use powerful AI tools on Apple Macs because these tools only work with NVIDIA graphics cards and Linux.
**What's already out there:** No clear competitor yet.
**Who'd pay:** Developers with Apple Macs who want to run AI tools on their computers.
**How you'd win:** Make AI tools that usually need NVIDIA cards work on Apple Macs.
**First build:** Get one specific AI tool, like FreeToken, to run well on Apple Macs.
**Niche test:** Very specific: Apple Silicon Mac users who want to run FreeToken locally. Niche score: 4/5.
**Boring test:** This is about making software compatible with different hardware, which is often a boring but necessary task. Boring score: 4/5.
**Big-company risk:** high. The AI tool makers or Apple could add this support themselves.
**Confidence:** LOW. The makers of these AI tools or Apple might just add this feature.
**Sources:** [GitHub](https://github.com/FlashML-org/FreeToken/issues/9)

### AI Agent Credential and Access Management
**Category:** AI agents
**Problem:** Companies don't know how to safely give AI agents access to their systems without risking data leaks.
**What's already out there:** No clear competitor yet.
**Who'd pay:** Security teams and AI teams in companies using AI agents.
**How you'd win:** A security system made just for AI agents, giving very detailed control over what they can do.
**First build:** A tool that checks what AI agents are trying to do and stops them if they try to do something they shouldn't.
**Niche test:** Specific: security teams worried about AI agent API access. Niche score: 3/5.
**Boring test:** This is about security and access rules, which is very boring but critical for companies. Boring score: 4/5.
**Big-company risk:** high. Big cloud companies (AWS, Google, Azure) or AI platforms (OpenAI) could build this.
**Confidence:** low. A big cloud company or AI platform could easily add this as a core feature.
**Sources:** [Hacker News](https://github.com/onecli/onecli)
